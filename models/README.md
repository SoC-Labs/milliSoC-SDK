# models — Ethos-U model images for the milliSoC flash

This directory holds the source model(s), their runtime test vectors and the
Vela configuration used by the milliSoC flow. The compiled model image is
stored in QSPI flash **above the code images**, so it can be updated
independently of the application.

## Available models

| Model | `.tflite` | NPU MACs/inference | Weights (flash) | Arena (SRAM) | Runtime image | Ops |
| ----- | --------- | ----------------- | --------------- | ------------ | ------------- | --- |
| `hello_world_int8` | 2,704 B | 280 | 1,056 B | 64 B | 1,632 B | 3 (100 % offloaded) |
| `micro_speech_int8` | 18,800 B | 176,008 | 20,577 B | 14,400 B | 24,673 B | 4 (100 % offloaded) |

Both compile with `--output-format raw`, i.e. the whole graph runs on the NPU.
`hello_world_int8` is the default and is the smallest end-to-end check of the
Vela → flash → NPU pipeline. `micro_speech_int8` is the next step up: a
keyword-spotting depthwise-convolution network whose 176 K MACs per inference
are large enough for the throughput and utilisation numbers to mean something.

`keyword_scrambled_8bit.tflite` (the DS-CNN keyword model in the same
tflite-micro `models/` directory) is **not** usable: it contains
`SVDF`/`QUANTIZE`/`SOFTMAX` CPU operations and `vela --output-format raw`
refuses to emit a raw command stream for a graph with passthrough ops.

## Model choice: hello_world_int8

`hello_world_int8.tflite` is the TensorFlow Lite Micro "hello world" sine
benchmark, the smallest standard MCU model:

| Property            | Value                                   |
| ------------------- | --------------------------------------- |
| Source              | `tensorflow/tflite-micro` examples      |
| Input               | one int8 value (quantised)              |
| Topology            | 2 hidden dense layers + dense output    |
| Source file         | 2,704 bytes                             |
| NPU operators       | 3 (100 % offloaded to the Ethos-U85)    |
| MACs per inference  | 280                                     |
| Runtime image       | 1,632 bytes (header + cmd + weights)    |
| Command stream      | 476 bytes                               |
| Weights             | 1,056 bytes                             |

It is deliberately tiny: the point is to demonstrate the Vela → flash → NPU
pipeline, not to benchmark the NPU. The whole image fits in one 4 KiB flash
sector.

## Model choice: micro_speech_int8

`micro_speech_int8.tflite` is the TensorFlow Lite Micro keyword-spotting
("yes"/"no") model:

| Property            | Value                                        |
| ------------------- | -------------------------------------------- |
| Source              | `tensorflow/tflite-micro` examples           |
| Input               | 1,960 int8 values (40 × 49 spectrogram frame) |
| Topology            | depthwise conv 10 × 8 × 8, ReLU, dense 4000 → 4, softmax |
| Source file         | 18,800 bytes                                 |
| NPU operators       | 4 (100 % offloaded to the Ethos-U85)         |
| MACs per inference  | 176,008                                      |
| Runtime image       | 24,673 bytes (header + cmd + weights)        |
| Command stream      | 3,968 bytes                                  |
| Weights             | 20,577 bytes                                 |

Vela predicts ~15 k NPU cycles per inference at 8 MHz, i.e. ~1.9 ms, roughly
28× the sine model's work per cycle-normalised inference. It spans 7 flash
sectors and needs a 14.1 KiB arena, so the runtime arena is raised to 16 KiB
(see [SRAM budget](#sram-budget)).

## Test vectors

`vectors/<model>.h` holds the int8 inputs the runtime replays and the int8
outputs it expects, in the layout the testcase includes with
`-DMODEL_VECTORS_HEADER`. The Makefile derives the path from `MODEL`, so
switching models also switches vectors; there is no per-model code change.

* `hello_world_int8.h` is hand-written: the nine-value sine sweep from the
  TFLite Micro example with its reference outputs.
* `micro_speech_int8.h` is generated by `tools/gen_test_vectors.py`, which runs
  six synthetic spectrogram frames through the LiteRT (TFLite) integer kernels
  and records the results. Regenerate it after changing the source model:

  ```sh
  pip install ai-edge-litert
  python tools/gen_test_vectors.py \
      --model models/micro_speech_int8.tflite \
      --output models/vectors/micro_speech_int8.h
  ```

  The generated header records the model SHA-256, the input/output shapes and
  the accepted tolerance (2 LSB) in its comment block.

Both vector sets are tiny next to the models themselves: the whole
micro_speech set is 6 × 1,960 = 11.8 KiB of code image.

## Flash layout

The application image occupies flash from `0x000000` up to about `0x006900`
(current M85 + R5 images with the micro_speech vectors). The model starts at
`0x008000`, well clear of the code and on a 4 KiB sector boundary:

| Flash offset | Size     | Contents                                  |
| ------------ | -------- | ----------------------------------------- |
| `0x000000`   | ~26 KiB  | boot preamble + M85 image + R5 image      |
| `0x008000`   | 1,632 B (hello_world) / 24,673 B (micro_speech) | Vela model image |
| ...          |          | free                                      |

Keep the application image below `MODEL_FLASH_BASE`: flashing the app erases
every 4 KiB sector its image spans, so a larger app that crosses `0x008000`
would wipe the model. Move `MODEL_FLASH_BASE` (and re-flash the model) if the
code image grows past it. `tools/concat_hex.py` refuses to build a combined
image when the code overlaps the model blob.

The QSPI controller has a memory-mapped XiP/AHB window at `0x60000000`
(`FLASH_BASE` in `sys_memory_map.h`). Once the controller is in XiP/AHB mode,
the model is visible at:

```text
0x60000000 + 0x008000 = 0x60008000
```

Without XiP, the same bytes are read with the standard SPI READ command
(`0x03`) at flash address `0x008000`.

## SRAM budget

The NPU-visible SRAM at `0x30000000` is 64 KiB on the current bitstream, and
`u85_model` lays it out as:

| Offset   | Size    | Use                                              |
| -------- | ------- | ------------------------------------------------ |
| `0x0000` | 32 KiB  | model image copy (`MODEL_RUN_FROM_FLASH=0`)      |
| `0x8000` | 16 KiB  | feature-map arena: I/O, scratch, fast scratch    |

Per model that means:

| Model | Image copy | Arena | Total | Fits 64 KiB |
| ----- | ---------- | ----- | ----- | ----------- |
| `hello_world_int8` | 1,632 B | 64 B | 1.7 KiB | yes, by a wide margin |
| `micro_speech_int8` | 24,673 B | 14,400 B | 39,073 B | yes, ~25 KiB spare |

`person_detect` (the 150 × 150 person-detection model in the same tflite-micro
`models/` directory) does **not** fit: Vela needs a 148,992 B arena and the
image is 244,673 B, so it would need ~400 KiB of shared SRAM in copy mode, or
~150 KiB with `MODEL_RUN_FROM_FLASH=1`.

The runtime checks both limits against the image header and prints
`Model image FAIL` / `Model arena FAIL` instead of running if a model is too
big, so a too-large model fails loudly rather than corrupting the arena.

## Flow

Requirements:

* `vela` on `PATH` (developed with Ethos-U Vela 5.2.0)
* Python 3 with `numpy` for `tools/model_to_image.py`

Build the image:

```sh
make model
```

This runs:

1. `vela models/<MODEL>.tflite --config models/millisoc_vela.ini
   --system-config MilliSoC_U85 --memory-mode MilliSoC_Flash
   --output-format raw`
2. `tools/model_to_image.py` on the raw `.npz` output, taking the MAC count
   from Vela's summary CSV

and writes to `build/models/`:

| File                                  | Use                                       |
| ------------------------------------- | ----------------------------------------- |
| `<MODEL>_vela.npz`                    | Vela raw output (cmd/weights/regions)     |
| `<MODEL>_image.bin`                   | packed runtime image                      |
| `<MODEL>_image.hex`                   | one byte per line, for the flash programmer |
| `<MODEL>_image.json`                  | base, offsets, sizes, regions, MACs, CRC32 |
| `<MODEL>_image.h`                     | C constants for a future linked-in build  |
| `<MODEL>_summary_*.csv`               | Vela per-layer summary                    |

The image is not a `.tflite` file: Vela's raw output already separates the
command stream from the weights, and the Ethos-U consumes exactly those two
buffers. `tools/model_to_image.py` adds a 96-byte header so the runtime can
program the NPU without parsing a flatbuffer.

The `.hex` is padded with `0xFF` to a 16-byte boundary (four 32-bit words):
the flash programmer pushes the QSPI FIFO 16 bytes at a time and a partial
trailing burst does not complete, so every hex file that gets programmed —
combined or model-only — must end on that boundary. The `.bin` keeps its exact
length; the runtime uses the header's `image_size`.

### Combined code + model image

The Makefile can append the model image to an application hex:

```sh
make TESTNAME=u85_model APPEND_MODEL=1
```

`tools/concat_hex.py --blob 0x008000:<image.bin>` fills the gap with `0xFF`,
checks that the code does not overlap the blob, and writes one hex file that
programs both. This is the recommended flow: one flash operation, no stale
model left behind.

To update only the model:

```sh
make flash_model
```

This flashes `build/models/hello_world_int8_image.hex` at `0x008000` through
the same DSTREAM/`armdbg` path as the application. It erases only the 4 KiB
sectors the model spans, so the code image below it is untouched.

## Vela configuration

`millisoc_vela.ini` describes the milliSoC memory system:

```ini
[System_Config.MilliSoC_U85]
core_clock=1e9
axi0_port=Sram
axi1_port=OffChipFlash
...

[Memory_Mode.MilliSoC_Flash]
const_mem_area=Axi1
arena_mem_area=Axi0
cache_mem_area=Axi0
```

* `axi0_port` is the SRAM port at `0x30000000`, reachable by both the M85 and
  the Ethos-U.
* `axi1_port` is the off-chip flash / XiP port. Vela places the read-only
  weights there.
* `const_mem_area=Axi1` puts the weights in flash; `arena_mem_area` and
  `cache_mem_area` put feature maps and scratch in SRAM.

With this plan Vela emits no DMA staging operations and no fast-scratch buffer:
the NPU reads weights directly from region 0 (flash), and all feature maps live
in region 1 (SRAM).

The Makefile knobs are:

| Variable             | Default                    | Meaning                                      |
| -------------------- | -------------------------- | -------------------------------------------- |
| `MODEL`              | `hello_world_int8`         | source model in `models/` (without `.tflite`) |
| `MODEL_FLASH_BASE`   | `0x008000`                 | flash offset of the image                    |
| `ACCEL_CONFIG`       | `ethos-u85-128`            | Vela accelerator (`ethos-u85-128/256/512/1024/2048`) |
| `VELA_CONFIG`        | `models/millisoc_vela.ini` | Vela system/memory configuration             |
| `VELA_SYSTEM_CONFIG` | `MilliSoC_U85`             | section in `VELA_CONFIG`                     |
| `VELA_MEMORY_MODE`   | `MilliSoC_Flash`           | memory mode section in `VELA_CONFIG`         |
| `APPEND_MODEL`       | `0`                        | `1` embeds the image in the app hex          |
| `MODEL_RUN_FROM_FLASH` | `0`                      | `1` lets the NPU fetch cmd/weights from flash |

Example — build and flash the keyword-spotting model:

```sh
make model MODEL=micro_speech_int8
make run_hw TESTNAME=u85_model APPEND_MODEL=1 MODEL=micro_speech_int8
```

`MODEL` also selects the test vectors (`models/vectors/<MODEL>.h`); the build
stops with a clear error if the model has no vector header.
`make model_report` re-runs Vela with `--supported-ops-report` and writes
`SUPPORTED_OPS.md` into `build/models/`.

## Notes

* Vela resolves `--config` relative to its own `ethosu/config_files` directory,
  so the Makefile passes an absolute path (`$(abspath ...)`). A relative path
  produces a confusing "file not found" error.
* The sine model declares a dynamic batch axis. Vela fixes it to 1 and prints
  four `dynamic signature in axis 0` notices; this is expected.
* `ACCEL_CONFIG` must match the NPU configuration in the RTL. The current
  default is `ethos-u85-128`; change it if the bitstream uses a different MAC
  count. The NPU `CONFIG` register (`0x44032028`) reports the implemented
  configuration.
* The runtime image is self-describing (magic `MVL1`, version 1, CRC32 over
  cmd + weights, and Vela's `nn_macs` in the word after the CRC). The header
  layout is documented in [`apps/u85_model/README.md`](../apps/u85_model/README.md).

## Running the model

The testcase is [`apps/u85_model`](../apps/u85_model). It reads the image from
flash, checks the header and CRC, and then runs the command stream on the
Ethos-U85. Because the current FPGA does not give the NPU bus access to the
flash window, the default mode copies the image into SRAM at `0x30000000`
first. The direct-from-flash path is implemented behind
`MODEL_RUN_FROM_FLASH=1` and only needs the RTL change.

The runtime is model-agnostic: the input/output sizes, arena size and MAC count
come from the image header, and the test vectors from `models/vectors/`. The
only model-specific knowledge left in `apps/u85_model` is the SRAM budget
(`MODEL_ARENA_OFFSET`/`MODEL_ARENA_SIZE`).
